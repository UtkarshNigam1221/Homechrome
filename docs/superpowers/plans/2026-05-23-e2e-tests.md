# E2E Test Suite Implementation Plan

**Goal:** Author a Playwright-based end-to-end test suite that runs against deployed dev env, covers critical user flows, and gates pre-merge in CI.

**Tech:** Playwright (TypeScript), GitHub Actions, runs against `https://dev-*.homechrome.in`.

**Scope:** ~15 specs covering admin + storefront + integration. ~80% regression coverage. Phase 1 = 7 specs (MVP).

---

## Why Playwright

- Headless Chromium + Node — runs in CI without GUI
- Parallel execution, retries, screenshots on fail, trace viewer
- TypeScript-native (matches storefront stack)
- Mature for e-commerce (used by Shopify, Vercel)
- Alternative considered: Cypress (heavier, slower CI), custom Node (loses fixtures + reporting)

## CI Workflow

`.github/workflows/e2e.yml`:

```yaml
name: E2E Tests

on:
  pull_request:
    types: [labeled]
  workflow_dispatch:
    inputs:
      environment:
        description: 'Target env'
        required: true
        default: 'dev'

jobs:
  e2e:
    if: github.event.label.name == 'needs-e2e' || github.event_name == 'workflow_dispatch'
    runs-on: ubuntu-latest
    timeout-minutes: 30

    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'
          cache-dependency-path: e2e/package-lock.json

      - name: Install dependencies
        working-directory: e2e
        run: npm ci

      - name: Install Playwright browsers
        working-directory: e2e
        run: npx playwright install --with-deps chromium

      - name: Run E2E
        working-directory: e2e
        env:
          E2E_BASE_URL_ADMIN: ${{ vars.E2E_BASE_URL_ADMIN }}
          E2E_BASE_URL_STORE: ${{ vars.E2E_BASE_URL_STORE }}
          E2E_BASE_URL_API: ${{ vars.E2E_BASE_URL_API }}
          ADMIN_EMAIL: ${{ secrets.E2E_ADMIN_EMAIL }}
          ADMIN_PASSWORD: ${{ secrets.E2E_ADMIN_PASSWORD }}
          TEST_PHONE_NUMBER: ${{ vars.E2E_PHONE }}
        run: npx playwright test

      - uses: actions/upload-artifact@v4
        if: failure()
        with:
          name: playwright-report
          path: e2e/playwright-report
          retention-days: 7
```

**Required GitHub secrets:**
- `E2E_ADMIN_EMAIL`, `E2E_ADMIN_PASSWORD`

**Required GitHub vars:**
- `E2E_BASE_URL_ADMIN`, `E2E_BASE_URL_STORE`, `E2E_BASE_URL_API`, `E2E_PHONE`

**Trigger:** Add `needs-e2e` label to PR → workflow fires. Or via Actions tab → workflow_dispatch.

## Test Isolation

- Every test creates unique product (SKU prefix `E2E-`)
- afterEach hook deletes via API even if test fails
- Failures uploaded as Playwright trace zip + screenshots for debugging
- No shared state between tests (parallel-safe)

---

## Auth Strategy

### Admin
- Use `storageState` — login once globally via `globalSetup`, save cookies to file, reuse across all admin tests
- Refresh cookies if expired between runs (admin TTL = 15min, runs typically <30min)

### Customer (OTP)
- Backend dev mode: MSG91 DevClient logs OTP to backend stdout — fetchable via CloudWatch log query (slow + brittle)
- Better: backend exposes test-only endpoint `GET /api/v1/store/auth/dev-otp?phone=...` that returns the most recently sent OTP. Add only when `APP_ENV=development`. Out of scope for plan but worth adding.
- Fallback: use a canned phone number that always returns OTP `123456` in dev mode.

## Maintenance

- **Add E2E test when:** new user-facing flow lands OR major bug shipped (regression).
- **Remove/skip when:** flow deprecated.
- **Quarantine:** mark flaky tests with `test.fixme()` while debugging.
- **Run cadence:** PR-triggered via `needs-e2e` label + nightly cron in CI.
